# Thin-market curves for Environment B

Generated by `scripts/run_thin_market.py`, committed so the THEORY.md §10.5 tables
can be checked without re-running the sweep.

    python scripts/run_thin_market.py --output-dir data/processed/thin_market

Three directories share this script and differ only in the acceptability bar, so
this file documents all three. See also `../THIN_MARKET_README.md`, which reads the
curve across the three bars.

## Regime

Environment B, the `complete` arm: full-information matching over the subgraph the
entry filter admits. N = 1000 from `experiments/base.yaml`, seeds 42 to 46, a size
fraction grid from 0.01 to 1.00, and 100 replicates per grid point. **Epoch 0 only**:
θ as calibrated, no feedback, nothing learned.

**The committed file was generated in the inert regime, `admissible_fraction: 0.2`**,
not the 0.02 the config ships today. `run_thin_market.py` reads
`SimConfig.from_yaml()` with no config override, so reproducing this file exactly
means pinning that value; at 0.02 the acceptability columns move and the file does
not reproduce.

The bar is what separates the three directories:

| directory | bar |
|---|---|
| `thin_market/` | each agent's own θ, the calibrated 0.8 utility quantile |
| `thin_market_q0.95/` | each agent's 0.95 utility quantile, via `--bar-quantile 0.95` |
| `thin_market_q0.99/` | each agent's 0.99 utility quantile, via `--bar-quantile 0.99` |

`clearance_prob` is identical across the three; only the acceptability columns and
`critical_mass` differ.

## Files

| file | contents |
|---|---|
| `curve_seed<seed>.csv` | one row per size fraction, for one seed (42 to 46) |
| `curve_mean.csv` | the same averaged over seeds, with `clearance_sd` between seeds |

| column | meaning |
|---|---|
| `size_fraction` | the share of A's population admitted to B |
| `eligible_n`, `empty_share`, `n_dropped` | the subgraph actually built at that size |
| `clearance_prob` | share of eligible agents matched |
| `p_acceptable`, `p_acceptable_analytic`, `p_acceptable_exact` | the three ways of computing the bar's pass rate |
| `critical_mass` | interior crossing of the clearance curve |

## Thread count

**24, and it cannot matter here.** This directory predates `ncf.num_threads`, so its
run took whatever count torch read from the machine, and the development machine
reports 24. But the `complete` arm trains no model: `thin_market_curve` calls no
torch code at all, and the C++ it does call is bitwise identical at every thread
count (`docs/INTERFACES.md` §3.1). Re-run on 2026-10-25 at the committed regime, every
column reproduces to within 6e-17 relative, which is the compiler ulp caveat in §3,
not a thread effect.

So the count is recorded for completeness and does not need to be set to regenerate
this directory.

## Reading the curve

See `../THIN_MARKET_README.md`. In one line: only the rise is the thin-market
penalty, the fall is the k = 20 truncation, and the curve is not support for H4.

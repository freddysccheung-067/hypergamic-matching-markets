# Thin-market curves, 0.95 acceptability bar

Generated by `scripts/run_thin_market.py`, committed so the THEORY.md §10.5 tables
can be checked without re-running the sweep. This is one of three directories the
script writes; the shared design is documented in `../thin_market/README.md` and the
cross-directory reading in `../THIN_MARKET_README.md`.

    python scripts/run_thin_market.py --bar-quantile 0.95 \
        --output-dir data/processed/thin_market_q0.95

## Regime

Identical to `../thin_market/` in every respect except the bar: Environment B, the
`complete` arm, N = 1000, seeds 42 to 46, the size-fraction grid from 0.01 to 1.00,
100 replicates per point, epoch 0 only.

The bar here is each agent's **0.95 utility quantile** rather than its own calibrated
θ. That raises the acceptability threshold from the 0.8 quantile to the 0.95 one,
which makes pool size matter: the critical mass at ρ = 0.5 rises from 3.1 to 13.3.
`clearance_prob` is unchanged from `../thin_market/`; only the acceptability columns
and `critical_mass` differ.

The committed file was generated in the inert regime, `admissible_fraction: 0.2`,
like its sibling; see that README for why reproducing it needs that value pinned.

## Files

| file | contents |
|---|---|
| `curve_seed<seed>.csv` | one row per size fraction, for one seed (42 to 46) |
| `curve_mean.csv` | the same averaged over seeds, with `clearance_sd` between seeds |

Column meanings are listed in `../thin_market/README.md`.

## Thread count

**24, and it cannot matter here.** This directory predates `ncf.num_threads`, so its
run took whatever count torch read from the machine, and the development machine
reports 24. The `complete` arm trains no model, so no torch reduction is involved and
no thread count can change a number (`docs/INTERFACES.md` §3.1).

To regenerate, the thread count does not need to be set; the acceptability bar and
the regime do.

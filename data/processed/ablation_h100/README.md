# Ablation data, 100-epoch horizon

Generated by `scripts/run_ablation.py` on 2026-10-24, committed so the horizon dependence of the
NCF-versus-oracle gap can be checked without re-running the simulation.

    python scripts/run_ablation.py --config experiments/base.yaml \
        --seeds 42,43,44,45,46 --output-dir data/processed/ablation_h100/

That command reads `experiments/base.yaml` as shipped: `admissible_fraction: 0.02` (the live
regime), `n_epochs: 100`, N = 1000, k = 20. Nothing is overridden, so this is the one directory
whose numbers are reproducible from the shipped config with no edits.

## Regime

Same populations as `data/processed/ablation_live/` (seeds 42-46, same config) run five times
longer. The first 20 epochs of the two directories are identical row for row, which is the check
that the horizon is the only thing that differs.

## Result

Final-epoch Gini, mean ± sd over five seeds:

| arm | epoch 19 (`ablation_live`) | epoch 99 (this directory) |
|---|---|---|
| `random` | 0.4214 ± 0.0049 | 0.3559 ± 0.0039 |
| `oracle` | 0.6545 ± 0.0111 | 0.6545 ± 0.0111 |
| `ncf` | 0.9412 ± 0.0033 | 0.6796 ± 0.0183 |
| `popularity` | 0.9600 ± 0.0000 | 0.9600 ± 0.0000 |

Gap, paired by seed:

| gap | epoch 19 | epoch 99 |
|---|---|---|
| `gini(ncf) − gini(oracle)` | +0.2867 ± 0.0101 | **+0.0251 ± 0.0078** |

The per-epoch trajectory of that gap (mean over seeds): +0.2633 at epoch 0, a peak of +0.3055
at epoch 5-6, +0.2867 at epoch 19, +0.2625 at 29, +0.1750 at 49, +0.0682 at 74, +0.0251 at 99.
It is positive on every seed at epoch 99 (0.0293, 0.0338, 0.0284, 0.0152, 0.0189). NCF reach
climbs from 4.1% at epoch 0 to 95.7% at epoch 99.

## Reading it

Estimation-error concentration is a **cold-start property that relaxes**. While the filter has
seen little, it ranks nearly everyone the same and most agents are on no shortlist. As it learns
coverage the gap closes toward, but does not reach, the oracle. A 20-epoch figure of +0.285 or
+0.287 describes the first fifth of this run, not where it settles. Quote the horizon with the
number.

The oracle column is identical across the two horizons because the oracle arm has no state that
learns, and its Gini has settled by epoch 4 (THEORY.md §3).

## Files

| file | contents |
|---|---|
| `<arm>_seed<seed>.csv` | one row per epoch (100), the full metrics table |
| `summary.csv` | mean and sd of each metric at the final epoch, per arm, over the five seeds |
| `gaps.csv` | the three per-seed gaps at the final epoch, mean and sd |

## Thread count

**24, verified.** This directory predates `ncf.num_threads`, so the count was whatever torch read
from the machine and the development machine reports 24. Re-run on 2026-10-25 at
`ncf.num_threads: 24`, the `ncf` arm for seed 42 reproduces every column of `ncf_seed42.csv`
exactly across all 100 epochs, including the epoch-99 Gini of 0.6935411 that
`docs/INTERFACES.md` §3 cites. The same run at the shipped default of 1 gives 0.6976498, which is
not the committed number.

Of the three ablation directories this is the only one that reproduces with the shipped config and
no other override: it was generated after the last change to the NCF scoring path, so the code that
produced it is the code in the repository. The other two reproduce at 24 threads as well, but only
once their own regime is pinned as well (`../ablation/` needs `admissible_fraction: 0.2`, and
`../ablation_live/` needs `--epochs 20`).

To regenerate exactly, set `ncf.num_threads: 24`. The shipped default of 1 remains correct for new
work; this count is recorded to explain the file, not to recommend the setting.

## Quoting these numbers

Every figure is a mean ± sd over five independent populations. The seed spread says the
simulation is stable, not that the result generalizes: the model has no empirical calibration.
See THESIS.md for what these results can and cannot support.

# H1: the separating curve

Generated by `scripts/run_separating.py`, committed so the H1 direction quoted in
THESIS.md and the separating-curve figure in THEORY.md §10.2 can be checked without
re-running the sweep.

    python scripts/run_separating.py

The script writes to this path by default. It takes about two seconds, because it
runs no training: every row is one **epoch-0 swipe log** on the shipped weights,
before any feedback has acted.

## Regime

N = 1000, five seeds (42 to 46), and eleven signal costs: 0.0, 0.05, 0.10, then
0.25 steps from 0.25 to 2.00.

**The committed file was generated in the inert regime, `admissible_fraction: 0.2`**,
not the 0.02 that `experiments/base.yaml` ships today. That is not documented
anywhere else in this directory and it changes the numbers substantially: at 0.02
the same script produces half the proposals (10000 rather than 20000 at `c = 0`,
seed 42) and a `v_bar` of 9.06 rather than 4.68. The script reads `base.yaml`
directly and has no `--config` flag, so reproducing this file exactly means editing
that file or calling `generate_swipes` with the 0.2 setting directly.

## Files

| file | contents |
|---|---|
| `h1.csv` | one row per (signal cost, seed): the measured quantities below |

| column | meaning |
|---|---|
| `signal_cost` | `hypergamy.signal_cost`, the `c` in the proposal decision |
| `n_proposals` | positives in the epoch-0 log |
| `mean_tau` | E[tau given proposal], the mean intent of the proposers |
| `v_bar` | pooled mean utility over θ-admissible candidates, both sides |
| `phat` | share of positive swipes the other side reciprocated |
| `tau_star` | `c / (v_bar * 0.5)`, the analytic cut using the `p` the decision is handed |
| `tau_star_phat` | the same cut using the measured accept rate instead |
| `tau_trunc` | mean of tau over agents above `tau_star`, what a pure cut predicts `mean_tau` to be |

## Thread count

**24, and it cannot matter here.** This directory predates `ncf.num_threads`, so its
run took whatever count torch read from the machine, and the development machine
reports 24. But nothing in `scripts/run_separating.py` trains a model: it calls
`sample_population`, `mean_admissible_utility` and `generate_swipes`, all of which
are C++ and all of whose parallel loops are bitwise identical at every thread count
(see `docs/INTERFACES.md` §3.1). Re-run on 2026-10-25 at the committed regime, the
file reproduces to the last bit of every value that was not carried through a
compiler's `exp`/`log`/`pow` (the difference is at 1e-16, which is the caveat in §3,
not a thread effect).

So the count is recorded for completeness and does not need to be set to regenerate
this directory.

## Quoting these numbers

Every figure is a mean over five independent populations, never a single run. H1 has
no registered interval in `docs/STATS.md`, so the paper reports its direction
qualitatively; a reader who wants one can compute it from `h1.csv`, which carries
`mean_tau` per (cost, seed). The seed spread says the simulation is stable, not that
the result generalizes, and the model has no empirical calibration.
